01 / FUNDAMENTALS

雲端運算是什麼？

透過網路，依需求存取共享且可配置的運算資源池；資源能快速提供與釋放，只需少量管理工作或供應商互動。

資源可以包括網路、伺服器、儲存空間、應用程式及服務。這是 NIST SP 800-145 的核心定義。

使用者的角度

不必親自管理所有實體設備，就能透過網路取得需要的運算能力。

供應商的角度

整合並管理運算資源，再依服務方式提供給不同使用者。

來源：CC-001（NIST SP 800-145，第 2 頁）；CC-002（Google Cloud，Cloud computing defined）
01 / FUNDAMENTALS

雲端運算的五項基本特徵

01 隨需自助服務

使用者可依需求自行配置運算能力，不必每次都人工聯繫供應商。

02 廣泛網路存取

透過網路及標準機制存取，支援不同用戶端平台。

03 資源池化

供應商整合資源，以多租戶方式服務使用者，並動態分配資源。

04 快速彈性

可依需求快速增加或釋放資源。

05 可衡量的服務

監控、控制並回報資源使用情況，作為服務管理與計量依據。

記憶重點

自助取得、網路存取、共享資源、彈性調整、使用量可衡量。

來源：CC-001；CC-006 第 3 節
01 / FUNDAMENTALS

雲端資源如何被使用？

以下是依 Wiki 內容整理的概念流程，呈現使用者如何透過網路取得遠端共享資源。

使用者提出資源需求
→
網路連線傳送服務請求
→
雲端平台配置共享資源
→
服務回應取得運算能力

資源池化

將運算、儲存及網路資源整合，依使用需求分配。

快速彈性

需求改變時，資源可增加或釋放，而不必完全依賴固定設備容量。

概念整理依據：CC-001、CC-002；此流程為教學示意，非來源原圖。
02 / SERVICE MODELS

三種雲端服務模式

差別在於供應商提供到哪一層，以及使用者能管理多少內容。

SaaS

Software as a Service

軟體即服務。使用者直接使用供應商提供的應用程式，底層環境主要由供應商管理。

使用現成軟體

PaaS

Platform as a Service

平台即服務。使用者將自行建立或取得的應用程式部署到供應商提供的平台。

部署應用程式

IaaS

Infrastructure as a Service

基礎設施即服務。使用者取得運算、儲存及網路等基礎資源，並管理作業系統與應用程式。

管理作業系統
來源：CC-001（NIST SP 800-145）；CC-004（NIST SP 800-146，第 5 節）
02 / SERVICE MODELS

服務模式：管理範圍比較

管理項目SaaSPaaSIaaS
使用應用程式使用供應商應用程式部署自行建立／取得的應用程式部署自行選擇的軟體
管理應用程式通常有限使用者使用者
管理作業系統供應商供應商使用者
管理實體資源供應商供應商供應商

快速理解

SaaS 著重「使用軟體」；PaaS 著重「部署應用」；IaaS 著重「取得基礎資源」。

評估提醒

不能只看產品名稱是否有「aaS」，還要檢查是否符合 NIST 五項雲端特徵。

來源：CC-001、CC-006（第 3～6 節）；管理範圍依 Wiki 整理。
03 / DEPLOYMENT MODELS

四種雲端部署模式

Private Cloud｜私有雲

基礎設施專供單一組織使用，可由組織、第三方或雙方管理。

Community Cloud｜社群雲

專供具有共同任務、安全需求、政策或法規遵循要求的組織群體使用。

Public Cloud｜公有雲

基礎設施開放一般大眾使用，由提供雲端服務的組織擁有、管理及營運。

Hybrid Cloud｜混合雲

由兩種或以上不同雲端基礎設施組成，透過技術連結支援資料及應用程式可攜性。

來源：CC-001（NIST SP 800-145）；CC-003、CC-006。NIST 正式分類保留四種模式。
03 / DEPLOYMENT MODELS

部署模式：如何判斷？

模式使用對象判斷關鍵
私有雲單一組織專供單一組織使用
社群雲特定組織群體成員有共同關注事項
公有雲一般大眾對大眾提供服務
混合雲依組合而定至少兩種不同雲端基礎設施連結

分類差異要留意

Google Cloud 入門文章以公有、私有及混合雲三種方式介紹；本 Wiki 的正式分類仍以 NIST SP 800-145 為準，因此保留社群雲。

來源：CC-001、CC-002、CC-003、CC-006
04 / ARCHITECTURE

NIST 雲端參考架構：五種角色

NIST 以廠商中立的高階架構描述參與者及其活動，不是特定供應商的實際系統設計。

Cloud Consumer

雲端消費者：與供應商建立業務關係並使用服務。

Cloud Provider

雲端供應商：負責讓雲端服務可供使用。

Cloud Auditor

雲端稽核者：獨立評估服務、運作、效能及安全。

Cloud Broker

雲端代理者：管理服務使用、交付及供應商與消費者關係。

Cloud Carrier

雲端承載者：提供供應商與消費者間的連線及傳輸。

角色關係

消費者使用服務；供應商提供服務；其他角色協助傳輸、協調或獨立評估。

來源：CC-003（NIST SP 500-292，第 2、3 節）
04 / ARCHITECTURE

雲端供應商的三層架構

NIST 以服務協調模型描述服務、資源抽象控制，以及實體資源之間的關係。

Service Layer｜服務層SaaS、PaaS、IaaS；提供消費者存取服務的介面
Resource Abstraction and Control Layer資源抽象與控制：Hypervisor、VM、虛擬儲存、配置、存取控制與使用量監控
Physical Resource Layer｜實體資源層CPU、記憶體、網路設備、儲存設備、電力、冷卻與通訊設施
來源：CC-003（NIST SP 500-292，第 3.2 節）。此圖為依文字整理的教學示意。
04 / ARCHITECTURE

虛擬化與資源抽象

資源抽象與控制層透過軟體方式管理實體運算資源，讓底層資源能以虛擬資源形式配置與使用。

●Hypervisor：屬於資源抽象元件的例子。
●虛擬機器（VM）：以虛擬化方式提供運算環境。
●虛擬儲存：將儲存資源以抽象方式提供。
●控制元件：負責資源配置、存取控制及使用量監控。

概念示意

虛擬資源VM／虛擬儲存
抽象與控制配置、監控、存取控制
實體設備CPU／記憶體／儲存／網路
來源：CC-003（NIST SP 500-292，第 3.2 節）；示意圖非原始文件圖表。
04 / ARCHITECTURE

雲端服務管理不只看技術

Business Support

客戶管理、合約、會計及定價等業務支援。

Provisioning & Configuration

服務供應、配置及服務等級管理。

Portability & Interoperability

資料、系統及服務在不同雲端環境間的可攜性與互通性。

選擇雲端服務時，除了功能，也要思考合約、配置管理，以及未來能否移轉或與其他環境互通。
來源：CC-003（NIST SP 500-292）；CC-004（NIST SP 800-146）
05 / SECURITY

雲端安全：跨越整個架構

安全不是單一設備或單一角色的工作，而是從實體設施到應用程式都需要考量的議題。

身分與存取

身分驗證、授權、身分管理。

資料保護

機密性、完整性及資料治理。

服務維運

可用性、稽核、安全監控及事件應變。

安全思考範圍

實體安全基礎設施網路平台應用程式資料與帳號
來源：CC-003（NIST SP 500-292，安全與隱私章節）
05 / SECURITY

使用雲端前，必須評估的風險

連線與服務持續性

網路依賴、延遲、連線中斷及供應商服務中斷。

資料與移轉

資料可攜性、互通性、資料所在地及災難復原。

安全與隱私

非預期資料揭露、多租戶隔離、瀏覽器安全及金鑰管理。

虛擬化環境

虛擬機器蔓延、VM 隔離及資料清除。

來源：CC-004（NIST SP 800-146，第 8、9 節）。該文件發布於 2012 年，當前產品與法規仍應查閱現行文件。
05 / SECURITY

共同安全責任：依服務模式而不同

模式供應商責任概況客戶仍需注意
IaaS底層基礎設施與實體安全作業系統、資料、存取政策及工作負載安全
PaaS底層平台與較多託管控制應用層控制、IAM、資料與用戶端保護
SaaS承擔大部分服務安全責任存取控制及自己選擇儲存的資料

Google Cloud Shared Fate

Google Cloud 在共同責任之外提出更密切合作的安全概念，例如提供最佳實務指引、安全基礎設施程式碼及整合式安全解決方案。

重要界線：以上責任例子及 Shared Fate 皆依 CC-007（Google Cloud）整理，不代表所有供應商通用標準；實際責任依服務與設定而異。
06 / USE CASES

雲端運算的常見應用

資料儲存與備份

保存大量資料、提高可存取性，並支援備份與災難復原。

應用程式開發

提供開發、部署及測試所需工具與環境。

大數據分析

運用雲端資源處理大量資料，支援研究與分析。

彈性擴充

面對流量或業務需求變動時，依需求調整運算資源。

混合雲備援

平時使用私有雲，需求高峰時搭配外部雲端資源。

生活與協作

透過網路使用儲存、應用程式及各類線上服務。

來源：CC-002（Google Cloud）；CC-004（NIST SP 800-146，第 4、8、9 節）；CC-005
06 / EVALUATION

選擇雲端服務前的檢查方向

服務是否符合雲端定義？

檢查五項基本特徵，而非只看產品名稱。

服務模式與部署模式？

確認使用者管理範圍，以及資源供誰使用。

資料與安全責任？

釐清存取控制、資料所在地、法規及雙方責任。

成本與退出方式？

評估使用成本、資料移轉、可攜性、互通性及供應商中斷風險。

來源：CC-006（NIST SP 500-322 的服務與部署模式評估工作表）；CC-004。

重點回顧

雲端是資源服務模式

透過網路依需求取得共享、可配置的運算資源。

三種服務模式

SaaS、PaaS、IaaS，差異在管理與控制範圍。

四種部署模式

私有、社群、公有、混合雲。

技術與安全並重

理解架構層次，也要釐清風險與共同責任。

雲端不只是把資料放到網路上，而是一種整合、配置與交付運算資源的方式。
